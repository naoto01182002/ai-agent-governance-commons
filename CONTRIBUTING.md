# Contributing

Thank you for your interest in AI Agent Governance Commons.

This repository is a public draft standard and practical template set for AI agent governance. Contributions are welcome when they improve clarity, transferability, auditability, and practical use in RFPs, design documents, audit logs, RACI, self-assessment, and A2A responsibility-boundary documentation.

## Contribution Principles

Please follow these principles when proposing changes:

- Keep the standard minimal and transferable.
- Do not turn this repository into a vendor-specific implementation guide.
- Do not imply certification, compliance, legal approval, safety guarantee, or external audit.
- Separate required minimum explanation items from optional examples.
- Prefer wording that can be copied into RFPs, design documents, audit checklists, RACI tables, and self-assessment documents.
- Make responsibility, authority, approval, stop-right, rollback, and audit boundaries explicit.
- Do not make an AI agent Accountable in RACI.

## Accepted Contribution Types

| Type | Description |
| --- | --- |
| Editorial | wording, typo, structure, readability |
| Standard Change | Minimum Viable Standard or governance item change |
| Template Change | RFP, design, audit log, RACI, self-assessment, or A2A template change |
| Example Addition | practical usage example that helps adoption |
| Risk Concern | unsafe, misleading, over-claiming, or responsibility-blurring guidance |

## Pull Request Expectations

For small editorial changes, a concise explanation is enough.

For standard, template, or governance changes, please explain:

- Problem
- Proposed change
- Reason
- Impact on existing templates
- Whether the change affects the Minimum Viable Standard item set
- Whether the change affects RFP, design, audit log, RACI, self-assessment, or A2A usage

## What This Repository Is Not

This repository is not:

- a certification program
- a compliance judgment body
- a legal advisory service
- a product implementation guide
- a vendor evaluation service
- an AI safety guarantee

Please avoid wording that could make readers believe otherwise.

## Issue Usage

Use GitHub Issues for concrete, actionable proposals or problems.

Use the most relevant issue template when available:

- Standard Proposal
- Template Feedback
- Wording Clarification
- Governance Risk Concern
- Bug or Repository Maintenance

## Discussion Style

Contributions should focus on the artifact, not the person.

Strong criticism of wording, structure, assumptions, and governance design is acceptable when it improves the standard. Personal attacks, harassment, or bad-faith arguments are not acceptable.
