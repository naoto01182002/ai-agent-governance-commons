# note Draft: AIエージェントを企業で使う前に、まず決めるべきこと

## タイトル案

AIエージェントを企業で使う前に、まず決めるべきこと

権限・監査・責任・停止権をRFPに書ける形にする

## リード

AIエージェント活用は進む。しかし企業システムに入れるとき、問題になるのはAIの賢さだけではない。

誰の代理で動くのか。どの権限を持つのか。何を参照したのか。何を提案し、何を実行したのか。誰が承認し、誰が止められるのか。事故時に誰が説明責任を負うのか。

これらをRFP、設計書、監査ログ、RACI、Self-Assessmentへ転記できなければ、AIエージェントは企業統制に接続できない。

## 本文構成

1. AIエージェント活用は進むが、権限と責任が曖昧になっている
2. 問題はAIの賢さではなく、誰の代理で何をしてよいかが説明できないこと
3. だから最低説明項目が必要になる
4. RFP、設計書、監査ログ、RACI、Self-Assessmentに転記できる形にした
5. GitHubで AI Agent Governance Commons v1.0 Public Draft を公開した
6. これは認証ではなく、実務で使って叩かれるための初期標準である

## 公開告知文

AI Agent Governance Commons v1.0 Public Draft を公開しました。

これは、AIエージェントを企業システム、SI、RFP、API、運用設計、監査設計に組み込む際の公共ドラフト標準と実務テンプレート集です。

AIが誰の代理で、どの権限を持ち、何を参照し、何を提案し、何を実行し、誰が承認し、誰が停止でき、誰が説明責任を負うのかを、RFP、設計書、監査ログ、RACI、Self-Assessmentへ転記できる形で整理しています。

含まれるもの:

- Minimum Viable Standard
- RFP追補テンプレート
- 設計書テンプレート
- 監査ログ標準
- AI Agent RACI
- A2A責任分界
- Human Sovereignty Gate
- Self-Assessment Checklist
- Evidence Package
- 用語集
- サンプル案件

これは認証、法的準拠、安全保証、外部監査、AIエージェント基盤の実装ではありません。

まず実務で使って、足りないところを見つけ、v1.1で直すためのPublic Draftです。

## 結び

AIエージェントを企業に入れるなら、モデルの性能だけでなく、権限、監査、責任、停止権を設計しなければならない。

モデルは借りてもよい。業務文脈、権限、監査ログ、停止権、責任分界は社会側に残す。

AI Agent Governance Commons は、そのための最小限の実務テンプレート集として公開する。
